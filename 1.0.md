## Overview

BNMSR Integration facilitates a way to allow for any addon mod (or MCreator workspace) to seamlessly integrate custom Miraculouses, Weapons, and Kwamis into BNMSR's shortcut menus and mechanics.

---

## API Versioning (Current Version: `1.0`)

BNMSR requires explicit API version handshake and payload verification. All integrations should declare `api_version: "1.0"`.

### Standalone Handshake
```java
// In your @Mod class or during InterModEnqueueEvent / FMLCommonSetupEvent
@SubscribeEvent
public static void onEnqueueIMC(InterModEnqueueEvent event) {
    // Tell BNMSR that your mod targets IMC API version 1.0
    InterModComms.sendTo("bnmsr", "api_version", () -> "1.0");
}
```

### Payload Field
```java
// Include "api_version" inside your registration payload:
CompoundTag tag = new CompoundTag();
tag.putString("api_version", "1.0");
tag.putString("id", "dragon");
// ...
InterModComms.sendTo("bnmsr", "register_miraculous", () -> tag);
```

## 1. Registering a Custom Miraculous

A Miraculous definition registers an active transformed miraculous item, one or more camo items, an optional Curios slot, its Kwami entities (happy and sad/hungry), and its theme color.

### IMC Registration Example
```java
// In your mod's @Mod class or during InterModEnqueueEvent
@SubscribeEvent
public static void onEnqueueIMC(InterModEnqueueEvent event) {
    CompoundTag tag = new CompoundTag();
    tag.putString("api_version", "1.0");
    tag.putString("id", "dragon");
    tag.putString("active_form", "mymod:dragon_miraculous_active");
    tag.putString("camo_forms", "mymod:dragon_camo_bracelet,mymod:dragon_camo_ring");
    tag.putString("curio_slot", "bracelet"); //or any custom one really
    tag.putString("kwami_entity", "mymod:longg");
    tag.putString("sad_kwami_entity", "mymod:longg_sad");
    tag.putInt("color", 0xE71D36);
    tag.putString("display_name", "Dragon Miraculous");
    tag.putString("favorite_food_tag", "forge:fruits");

    InterModComms.sendTo("bnmsr", "register_miraculous", () -> tag);
}
```

### Supported NBT Fields (`register_miraculous`)
| Field | Type | Description | Example |
|---|---|---|---|
| `api_version` | String *(optional)* | API version target | `"1.0"` |
| `id` | String | Unique identifier | `"dragon"` |
| `active_form` | String / CompoundTag | Active Miraculous item registry ID | `"mymod:dragon_miraculous_active"` |
| `camo_forms` | String / ListTag | Comma-separated item IDs or ListTag of items | `"mymod:camo_bracelet,mymod:camo_ring"` |
| `curio_slot` | String *(optional, defaults to "necklace")* | Curios slot identifier | `"bracelet"`, `"necklace"`, `"ring"` |
| `kwami_entity` | String *(optional)* | Entity ID for happy Kwami (leave empty if this miraculous has no Kwami) | `"mymod:longg"` |
| `sad_kwami_entity` | String *(optional)* | Entity ID for sad Kwami (used when hungry/sad) | `"mymod:longg_sad"` |
| `color` | int / Hex | Hex color for radial menu slices | `0xE71D36` |
| `display_name` | String *(optional)* | Hover / title label | `"Dragon Miraculous"` |
| `favorite_food_tag` | String *(optional)* | Forge item tag for feeding | `"forge:fruits"` |

## 2. Registering Weapon Radial Menus

BNMSR supports a weapon menu to switch between multiple forms when the NMS weapon menu key is pressed.

> [!WARNING]
> Weapon definitions require **at least 1 item variant**. You can optionally require an equipped helmet tag (e.g. `forge:dragon_masks`) or a specific boolean NBT tag on the held item.

### IMC Registration Example
```java
CompoundTag tag = new CompoundTag();
tag.putString("api_version", "1.0");
tag.putString("id", "dragon_weapon");
tag.putString("items", "mymod:dragon_sword{CustomModelData:1,Damage:0,is_transformed:true},mymod:dragon_ball,mymod:dragon_idksob_ifyouseethisimsleepdeprived");
tag.putString("helmet_tag", "forge:dragon_masks"); // optional
tag.putString("nbt_requirement_key", "is_transformed"); // optional
tag.putInt("color", 0xE71D36);
tag.putString("display_name", "Dragon Sword");

InterModComms.sendTo("bnmsr", "register_weapon_menu", () -> tag);
```

### Supported NBT Fields (`register_weapon_menu`)
| Field | Type | Description | Example |
|---|---|---|---|
| `api_version` | String *(optional)* | API version target | `"1.0"` |
| `id` | String | Unique identifier | `"dragon_weapon"` |
| `items` | String / ListTag | Comma-separated item IDs (at least 1 item) (can have NBT data) | `"mymod:blade,mymod:whip,mymod:bow"` |
| `helmet_tag` | String *(optional)* | Forge item tag required on helmet | `"forge:dragon_masks"` |
| `nbt_requirement_key` | String *(optional)* | Boolean NBT key required to be true on held weapon | `"is_transformed"` |
| `color` | int / Hex | Hex color for radial menu slices | `0xE71D36` |
| `display_name` | String *(optional)* | Label for radial menu options | `"Dragon Sword"` |

## 3. Registering Custom Kwamis

You can include kwami hiding/showing in to the quick kwami menu.

> [!NOTE]
> BNMSR doesn't spawn or despawn the kwami entity for you. You have to handle that in your mod using `on_kwami_toggled` or by checking `is_kwami_hidden`.

```java
CompoundTag tag = new CompoundTag();
tag.putString("api_version", "1.0");
tag.putString("id", "longg");
tag.putString("happy_entity", "mymod:longg");
tag.putString("sad_entity", "mymod:longg_sad");
tag.putString("curio_slot", "bracelet");
tag.putString("item_or_tag", "mymod:dragon_camo_bracelet");
tag.putString("favorite_food_tag", "forge:fruits");
tag.putInt("color", 0xE71D36);

InterModComms.sendTo("bnmsr", "register_kwami", () -> tag);
```

## 4. Event Listeners

To listen to events register a callback (`BiConsumer<Player, CompoundTag>`) via Forge `InterModComms` during `InterModEnqueueEvent` or `FMLCommonSetupEvent`:

| IMC Method | When Fired | Available NBT Tag Keys |
|---|---|---|
| `on_weapon_switch` | Player switches to another custom weapon variant | `weapon_id`, `variant_index`, `previous_index`, `new_item`, `previous_item`, `new_item_stack`, `previous_item_stack`, `hand` |
| `on_miraculous_selected` | Player selects a custom Miraculous from the radial wheel<br>*(fires irregardless of kwami visibility)* | `miraculous_id`, `curio_slot`, `item_id`, `item_stack`, `has_kwami`, `is_kwami_hidden` |
| `on_kwami_toggled` | Player toggles a custom Kwami in the radial menu | `miraculous_id`, `kwami_id`, `is_hidden`, `action`<br>*(action values: `"toggle"`, `"show_all"`, `"hide_all"`)* |

> [!NOTE]
> `on_miraculous_selected` fires whenever you click the miraculous in the quick miraculous menu, even if its kwami is hidden or not set. If you only want players to transform when their kwami is out, check `is_kwami_hidden` first.

### Subscribing to Events in Java
```java
@Mod.EventBusSubscriber(modid = "mymod", bus = Mod.EventBusSubscriber.Bus.MOD)
public class MyBnmsrEventListener {

    @SubscribeEvent
    public static void onEnqueueIMC(InterModEnqueueEvent event) {
        InterModComms.sendTo("bnmsr", "api_version", () -> "1.0");

        // 1. Listen for weapon variant switches
        InterModComms.sendTo("bnmsr", "on_weapon_switch", () -> (BiConsumer<Player, CompoundTag>) (player, data) -> {
            String newItem = data.getString("new_item");
            int variantIndex = data.getInt("variant_index");
            player.sendSystemMessage(net.minecraft.network.chat.Component.literal("Switched to variant " + variantIndex + ": " + newItem));
        });

        // 2. Listen for miraculous selection
        InterModComms.sendTo("bnmsr", "on_miraculous_selected", () -> (BiConsumer<Player, CompoundTag>) (player, data) -> {
            String miraculousId = data.getString("miraculous_id");
            boolean hasKwami = data.getBoolean("has_kwami");
            boolean isHidden = data.getBoolean("is_kwami_hidden");
            System.out.println("Miraculous selected: " + miraculousId + " (Has Kwami: " + hasKwami + ", Hidden: " + isHidden + ")");
        });

        // 3. Listen for Kwami toggle
        InterModComms.sendTo("bnmsr", "on_kwami_toggled", () -> (BiConsumer<Player, CompoundTag>) (player, data) -> {
            boolean isHidden = data.getBoolean("is_hidden");
            String action = data.getString("action"); // "toggle", "show_all", or "hide_all"
            System.out.println("Kwami toggled: " + data.getString("kwami_id") + " (Hidden: " + isHidden + ", Action: " + action + ")");
        });
    }
}
```

## 5. MCreator Plugin Integration

With the `bnmsr_integration` plugin installed in your MCreator workspace, you get dedicated Blockly blocks (hehe) under the **BNMS Refined** procedure category.

> [!IMPORTANT]
> Always place registration blocks (`Register BNMSR Miraculous`, `Register BNMSR Weapon Menu`) inside a procedure triggered by `On BNMSR Registration / IMC Setup`. This ensures all definitions are registered during mod startup on `FMLCommonSetupEvent`.

### Available Procedure Blocks:
- **Register BNMSR Miraculous**: Use the gear ⚙️ icon to add one or more camo item slots. Accepts both `MCItem` (visual item picker) and `String` (item ID). *(leave empty if this miraculous has no Kwami)*.
- **Register BNMSR Weapon Menu**: Use the gear ⚙️ icon to add weapon variant items. Accepts both `MCItem` and `String` IDs.
- **set kwami hidden for [player] miraculous ID [id] [boolean]**: Sets whether the custom kwami is hidden (`true`) or shown (`false`) for the player. (ACTUALLY HIDING THE KWAMI IS NOT HANDLED BY THE ADDON!!!!)
- **is kwami hidden for [player] miraculous ID [id]**: Returns boolean `true` if the kwami is currently hidden.
- **is BNMSR loaded**: Returns boolean `true` if BNMS Refined is active in the game instance.

### Available Global Triggers:
- `On BNMSR Registration / IMC Setup`: Fires during `FMLCommonSetupEvent` at mod startup on the mod bus. Use this trigger for registering all custom Miraculouses and Weapon Menus.
- `on BNMSR weapon switch`: Runtime action trigger when a player switches custom weapon forms (Provides `entity`, `itemstack` (new item), `olditemstack` (previous item), `world`, `x`, `y`, `z`).
- `on BNMSR miraculous selected`: Runtime action trigger when a player selects a custom Miraculous from the radial menu (Provides `entity`, `itemstack`, `world`, `x`, `y`, `z`). *(fires irregardless of kwami visibility; use **is kwami hidden** if you want to check before transforming)*.
- `on BNMSR kwami toggled`: Runtime action trigger when a player toggles a custom Kwami in the radial wheel (Provides `entity`, `world`, `x`, `y`, `z`).

## 6. Helmet Tags & NBT Checks

BNMSR supports tag-based requirements and automatic head piece visibility management.

- `forge:hide_head`: Put this on helmet items to hide the player's 3D hair/hat layer when equipped.
- `forge:hide_arms` / `forge:hide_full_arms`: Hides player arms for full suits.
- `forge:second_layer_hide`: Hides outer skin layer pieces (sleeves, jacket, pants).
- `forge:kwami_any_food`: Tag items that any custom Kwami will happily consume.

## 7. FAQ & Best Practices

<details>
<summary><strong>Does my mod require BNMS Refined as a hard dependency?</strong></summary>

> **No.** You do not need BNMSR declared in your `mods.toml` dependencies or in your `build.gradle` classpath.
</details>

<details>
<summary><strong>Where do <code>on_weapon_switch</code>, <code>on_miraculous_selected</code>, and <code>on_kwami_toggled</code> execute?</strong></summary>

> These callbacks are executed on the **Server thread** when receiving the client menu action packet. You can safely modify player inventory, apply mob effects, spawn particles, or award advancements directly inside the `(player, data) -> { ... }` consumer.
</details>

<details>
<summary><strong>Does BNMSR spawn or despawn my custom Kwami entity in the world?</strong></summary>

> **No.** BNMSR only tracks whether the kwami is hidden or shown in the quick kwami menu. You have to spawn or remove the kwami entity yourself in your mod when responding to <code>on_kwami_toggled</code>.
</details>

<details>
<summary><strong>What food does my Kwami accept if I omit <code>favorite_food_tag</code>?</strong></summary>

> If omitted or set to `null`, the Kwami defaults to `#forge:kwami_any_food`. Any item tagged under `#forge:kwami_any_food` will be accepted when right-clicking to feed.
</details>

<details>
<summary><strong>What exact string values are accepted for <code>curio_slot</code>?</strong></summary>

> Use exact Curios slot identifier tags (lowercase): `head`, `necklace`, `back`, `body`, `bracelet`, `hands`, `ring`, `belt`, `charm`, or `curio`. Do not use localized display names.
</details>
